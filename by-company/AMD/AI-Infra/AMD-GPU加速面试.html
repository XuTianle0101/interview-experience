面试流程概览

AMD 的 GPU 加速岗位面试主要考察 C/C++ 基础、GPU 架构理解、ROCm 生态经验以及性能优化能力。 整体节奏偏技术深度，每轮 45-60 分钟。

一面 — 基础 + 编程（45 min）
Q1: 介绍 GPU 的线程层次模型（Thread / Block / Grid）。基础
回答了 Thread 是最小执行单元，Block 内线程共享 Shared Memory 并可同步，Grid 是 Block 的集合。面试官追问了 Warp 的概念。
Q2: Shared Memory 和 Global Memory 的区别？Bank Conflict 是什么？基础
从带宽、延迟、可见性三个维度回答。Bank Conflict 举了矩阵转置的例子，解释了 padding 技巧。
Q3: 手撕代码 — 矩阵乘法 GPU Kernel。核心
写了 Tiled GEMM，用 __shared__ 做 tile，block 大小 16×16。面试官追问了如何选择 tile size 以及 occupancy 的影响。
二面 — 项目深挖 + 架构（60 min）
Q1: 深入聊简历上的模型推理加速项目。核心
讲了用 ROCm HIP 重写 CUDA Kernel 的经验，重点讨论了 memory coalescing 和 warp-level primitive 的使用。
Q2: ROCm 和 CUDA 的主要区别？迁移有哪些坑？核心
对比了 HIP 和 CUDA API 的映射关系，讲了编译宏 __HIP_PLATFORM_AMD__ 的使用，以及 RDNA 和 CDNA 架构在 Wave（对应 Warp）大小上的差异。
Q3: 如何 profiling 一个 GPU Kernel？你用过哪些工具？基础
提到了 ROCm Profiler（rocprof）、CUDA Nsight Compute，以及如何分析 roofline model 判断瓶颈是 compute-bound 还是 memory-bound。
三面 — 系统设计 + Manager（45 min）
Q1: 设计一个大规模推理服务，支持多模型并发部署。核心
从模型加载、显存管理（多租户 isolation）、请求调度（batch scheduling）三个层面设计，画了架构图。
Q2: 如果模型 A 的推理延迟突然变高，你怎么排查？核心
分层排查：应用层 → 推理引擎层 → Kernel 层 → 硬件层。提到用 rocprof 定位热点 Kernel，检查是否被其他模型抢占显存。
Q3: 你对 AMD 未来的 AI 生态怎么看？开放题
聊了 ROCm 开源生态的优势、MI300 系列在 LLM 推理上的潜力，以及和 NVIDIA 竞争的差异化路线。
HR 面（20 min）
常规问题
离职原因、职业规划、期望薪资、能否 onsite 等。HR 介绍了 AMD 的福利和团队氛围。

总结 & 建议

  • AMD GPU 岗位对 C/C++ 底层能力要求高，建议重点复习内存层次、Warp/Wave 调度、Bank Conflict 等概念
  • 有 ROCm 经验是加分项，没有的话至少要对 CUDA-ROCm 迁移有基本认知
  • 系统设计轮偏实战，会考察多模型部署、显存管理、性能排查等实际工程问题
  • 整体面试体验不错，面试官技术功底扎实，追问有深度但不会刁难
