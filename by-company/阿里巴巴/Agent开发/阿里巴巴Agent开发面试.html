阿里巴巴Agent开发面试

阿里巴巴 · offerseed 面经

公司：阿里巴巴 岗位：Agent 开发工程师 轮次：4轮技术 + HR 结果：流程中 日期：2026-09

面试流程

一面 — 基础 + 编程（60 min）
Q: 自我介绍 + 聊一下做过的 LLM Agent 项目。 基础
介绍了之前做的企业知识库 Agent，用 RAG + Function Calling 实现多轮对话。面试官追问了架构选型原因。
Q: Function Calling 和 ReAct 的区别？各自适用什么场景？ 核心
对比了两者：Function Calling 是模型原生能力，延迟低、结构化输出；ReAct 是 Reason+Act 范式，更灵活但 token 消耗大。简单工具调用用 Function Calling，复杂多步推理用 ReAct。
Q: 手撕代码 — 实现 Multi-Agent 通信的消息路由器。 核心
写了一个基于 pub/sub 的消息路由器，Agent 间通过 topic 订阅通信。面试官追问了如何保证消息顺序和幂等性，补了 sequence number + dedup map。
二面 — RAG 深挖 + 系统（60 min）
Q: 你的 RAG 系统召回率只有 60%，怎么排查和优化？ 核心
分层排查：chunk 策略（固定大小 vs 语义切分）→ embedding 质量 → 检索方式（向量 vs 混合检索）→ reranker。最后加了 BM25+向量融合 + bge-reranker，召回率提到 85%。
Q: Chunk 策略怎么选？固定大小切分有什么问题？ 核心
固定大小会截断语义。用过三种方案：(1) 按段落+overlap，(2) 用小模型做语义切分，(3) 基于文档结构（标题层级）切分。生产环境用第三种效果最好。
Q: 如果用户问题跨多个文档，你的系统怎么处理？ 核心
用了 multi-query + 交叉编码重排。先让 LLM 改写问题为 3 个子问题分别检索，再融合去重重排。还提到可以用 GraphRAG 处理跨文档实体关联。
Q: Agent 记忆系统怎么设计的？长对话 token 超限怎么办？ 核心
短记忆用 sliding window 保留最近 N 轮；长记忆做了摘要压缩 + 向量索引，按相关性检索召回。提到可用 Mem0 或自建记忆服务。
三面 — 架构设计 + Director（60 min）
Q: 设计一个企业级 Agent 平台，支持多租户、多模型、工具市场。 核心
画了整体架构：(1) 接入层做鉴权 + 限流，(2) Agent 编排层用 DAG 描述工作流，(3) 工具层统一 Tool Registry + 沙箱执行，(4) 模型层接多 Provider 做路由 fallback，(5) 数据层做多租户隔离 + 审计日志。
Q: 工具沙箱怎么设计？用户上传的代码怎么安全执行？ 核心
用了 Firecracker microVM 方案。每个工具执行在独立 microVM 里，限制 CPU/内存/网络/文件系统。比 Docker 轻量，比 WASM 功能全（支持任意语言）。
Q: Agent 执行过程中 LLM 调用超时了怎么处理？ 核心
三层兜底：(1) 请求层超时+重试+熔断，(2) Agent 层做了 checkpoint 机制可恢复执行，(3) 业务层降级到规则引擎兜底。提到可以把 Agent 状态序列化到 Redis 做断点续跑。
Q: 你们线上 Agent 的 P99 延迟是多少？怎么优化的？ 核心
优化前 P99 约 8s，主要瓶颈在多轮 LLM 调用。优化措施：(1) 流式输出降低 TTFT，(2) 工具调用并行化，(3) 小模型做意图分类减少大模型调用，(4) 缓存高频问答。优化后 P99 降到 3s 左右。
四面 — 交叉面 / 技术广度（45 min）
Q: 你怎么看 Agent 的发展方向？Workflow Agent 和 Autonomous Agent 哪个更实用？ 开放题
认为短期内 Workflow Agent（DAG 编排）更实用，可控、可调试、成本可预测；长期看 Autonomous Agent 在特定领域（如 coding agent）会突破。两者会融合：workflow 为骨架 + LLM 做智能路由。
Q: 用过哪些 Agent 框架？各自优缺点？ 基础
用过 LangChain（生态全但抽象过度）、LlamaIndex（RAG 方向更强）、AutoGen（多 Agent 交互好但调试难）、Dify（低代码易上手）。生产自研框架，只借鉴定思想。
Q: Prompt Engineering 有什么最佳实践？ 基础
总结了几条：(1) 结构化 prompt（role+instruction+context+constraint），(2) few-shot > zero-shot，(3) CoT 对复杂推理有效但增加 token，(4) 用 system prompt 固定角色和行为边界，(5) 负面约束比正面约束更容易失效。
HR 面（25 min）
Q: 为什么选阿里？对阿里云 AI 方向怎么看？
阿里云在 IaaS + PaaS + MaaS 全栈布局上有优势，通义千问模型迭代快，企业客户多意味着真实场景多。聊了对 ToB Agent 产品化的兴趣。
Q: 薪资期望、到岗时间、其他 offer 情况
正常沟通，HR 介绍了阿里 P6/P7 的级别体系和股票期权方案。

总结 & 建议

  • 阿里 Agent 岗位面试深度很高，RAG 和 Agent 架构是必考项，建议准备完整的 RAG 优化案例
  • 系统设计轮偏向真实工程问题：多租户、沙箱、容错、性能优化，不是纸上谈兵
  • 面试官会持续追问细节（chunk 策略选择、P99 优化具体手段），准备时要能说到落地层面
  • 交叉面会考察技术广度和观点判断力，要对 Agent 行业趋势有自己的思考
  • 整体流程 4 轮技术 + 1 轮 HR，周期约 2-3 周，体验专业
